# 완료 확인 기준

주요 결과를 마무리하거나 사용자가 “깔끔하게 다듬어”라고 했을 때 읽는다. 현재 요청 범위의 실제 요구를 우선하며 새 산출물을 자동으로 늘리지 않는다.

## 요구 사항과 결과를 맞춘다

- 요구한 질문마다 답이나 결과가 존재하는가? 빠진 항목은 완료로 표시하지 않는다.
- 파일명, 확장자, 저장 위치, 필수 항목이 지정과 일치하는가? 가이드에 없는 제출 규격을 임의로 정하지 않는다.
- 파일이 실제로 만들어졌고 다시 열리는가? 링크나 경로는 전달할 최종 버전을 가리키는가?
- 최신 수정 사항이 표·설명·그림·코드에 일관되게 반영되었는가? 기존에 유지하기로 한 부분이 남아 있는가?

## 결과에 맞는 확인을 한다

| 결과물 | 최소한 확인할 증거 |
| --- | --- |
| 데이터 분석 | 핵심 수치 재계산, 대상·기간·분모, 대표 사례와 합계 비교 |
| 코드·자동화 | 실제 입력으로 실행한 결과, 주요 오류 경로, 생성된 파일 |
| 문서·슬라이드 | 파일 다시 열기, 필수 내용, 글자·표·그래프의 잘림과 가독성 |
| 화면·대시보드 | 실제 렌더링과 핵심 조작, 데이터 표시, 최신 변경 반영 |

사용할 도구가 없어 시각 확인이나 실행을 하지 못했다면 무엇을 확인했고 무엇이 남았는지 구분한다. 파일 존재만으로 내용·시각 검증까지 통과했다고 하지 않는다.

검사가 0개이거나 모두 건너뛴 상태를 통과로 보고하지 않는다. 기존 검사는 대상과 조건이 그대로일 때 이전 근거라고 밝혀 재사용한다. AI가 자신의 답에 다시 동의한 것만으로 독립 검증이라고 하지 않는다.

## 사용자가 이해하고 활용할 수 있게 다듬는다

- 결과가 무엇이고 왜 도움이 되는지 앞에서 알 수 있는가? 판단에 필요한 기본 용어를 설명 없이 먼저 나열하지 않았는가?
- 실제 입력 하나가 규칙을 거쳐 결과가 되는 예가 도움이 되는 경우 포함했는가? 참고자료가 많다는 이유로 이해가 쉬워졌다고 판단하지 않는다.
- 어디를 열고 무엇을 보면 되는지, 중요한 한계와 다음 행동이 분명한가? 질문에 답하지 않고 절차 목록으로 대신하지 않는다.
- 같은 개념의 이름, 숫자·단위, 파일 경로, 링크, 중복 설명을 정리한다. 문장을 줄이면서 핵심 뜻·조건·근거를 지우지 않는다.

## 바뀐 부분만 다시 확인한다

표현만 고쳤다면 의미·숫자·단위·경로가 유지됐는지 확인한다. 계산이나 코드를 고쳤다면 영향받는 검사를 다시 한다. 이미 맞는 구조와 사용자 선택은 보존하며, 기본 개념·선택 이유를 지우거나 모든 개념을 처음부터 강의하는 식으로 다듬지 않는다.

## 기록은 실제 판단을 짧게 남긴다

문제에서 판단 근거를 요구하거나 작업이 길어 인계가 필요할 때만 다음 내용을 남긴다. 채팅으로 충분하면 별도 기록 파일을 만들지 않는다.

| 선택 | 선택 이유 | 근거 | 실제 확인 | 남은 한계 |
| --- | --- | --- | --- | --- |
| 실행한 접근이나 중요한 수정 | 목적에 비춘 이점과 감수한 점 | 파일·열·범위·출처 | 실행·계산·관찰 결과 | 결론에 영향을 주는 미확인 사항 |

사용자가 명시한 선택과 AI가 제안·수행한 일을 구분한다. 사후에 의사결정 과정이나 사용자 기여를 꾸미지 않는다.

## 마무리 기준

- 필수 요구가 충족되고 중요한 확인을 통과하면 결과를 전달한다. 새 근거가 없는 반복 검토나 선택적 꾸미기는 멈춘다.
- 시간이 부족하면 치명적 오류 수정과 열 수 있는 필수 제출물을 우선한다. 불완전한 부분은 영향과 함께 알린다.
- 외부 제출은 허용된 방식과 사용자의 지시에 따른다. 아직 제출하지 않았다면 “준비 완료”와 “제출 완료”를 구분한다.
