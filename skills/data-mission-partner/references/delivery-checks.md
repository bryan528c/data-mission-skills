# 완료 확인 기준

주요 결과나 최종 제출을 정리할 때 읽는다. 실제 요구와 지정 양식이 우선이다. 문서 수를 늘리는 것이 완료 조건이 아니다.

## 요구·구현·양식을 먼저 맞춘다

- 필수 요구마다 실제 결과 또는 명시된 미완료가 있는가? 기능별 완료와 통합 완료를 구분한다.
- 지정 파일명·형식·제목·필수 항목을 보존했는가? 별도 구조 지도나 인계로 공식 양식을 대체하지 않는다.
- 양식의 각 주장에 실제 코드·계산·검사 근거가 있는가? [지정 양식과 설계 이해](workflows/submission-understanding.md)로 사실과 의도를 대조한다. 못한 일을 작성했다고 완료되지 않는다.
- 결과 파일이 열리고 최신 입력·설정에 대응하는가? 화면·저장·내보내기가 서로 다른 결과를 가리키지 않는가?
- 병렬 작업자가 아직 같은 파일을 바꾸는가? 인계를 받은 통합 시점의 파일과 검사 기준을 맞춘다.

| 결과 | 확인할 근거 |
| --- | --- |
| 데이터 분석 | 대상·기간·분모·단위, 대표 사례의 별도 계산, 부분·전체 합계 |
| 프로그램·자동화 | 실제 입력과 주요 실패 경로, 저장·재실행·생성 결과 |
| 문서·교육·표·그래프 | 근거 문장·핵심 개념·필수 내용, 숫자·단위·열림·가독성 |
| 화면·운영 도구 | 허용된 실제 미리보기와 핵심 동작. 정적 코드·HTTP 응답 성공과 구분 |
| 계획·추천 | 생성과 별도 조건 검사, 충족하지 못한 대상·이유, 가정과 현재 한계 |

테스트 0개·전부 제외는 통과가 아니다. 같은 함수를 다시 실행한 값만으로 독립 검산이라고 하지 않는다. 이전 검사는 관련 조건이 그대로일 때 이전 근거라고 밝혀 재사용한다. 직접 확인할 도구가 없으면 무엇을 못 봤는지 적는다.

## 사람이 읽고 사용할 수 있게 한 번 다듬는다

결과와 도움이 앞에서 보이는가? 필요한 기초 개념과 이유가 빠지지 않았는가? 실제 입력 한 사례가 과정을 설명하는가? 어떤 경로·항목을 열어 무엇을 볼지 분명한가? 문서·화면·코드의 용어·숫자·단위·조건이 일치하는가?

중복과 과장된 “최적·완벽·완료” 표현을 줄이되 근거·한계를 지우지 않는다. 기존 장점과 사용자 선택을 유지한다. 모든 개념을 처음부터 강의하거나 전면 재작성하지 않는다.

## 영향받은 부분만 재확인하고 끝낸다

표현만 고쳤으면 의미·수치·경로를 확인한다. 코드·규칙을 고쳤으면 해당 검사와 설명을 함께 갱신한다. 중요한 결정은 **선택·이유·실제 근거·검증·한계**로 기존 양식에 짧게 기록한다. AI 제안과 사용자 결정, 실제 관측과 추정을 구분한다.

필수 결과와 중요한 검증이 끝났으면 선택 기능·계속된 꾸미기를 중단한다. 시간이 부족하면 치명 오류와 열리는 필수 파일부터 처리한다. 준비 완료·제출 확정·후속 단계 완료는 다르다. 최종 외부 제출은 명시적 권한과 규정을 따른다.

AI 금지 단계가 시작되면 모든 관련 세션의 실행·설명·초안·첨삭을 중단한다. 전환 대기 중 추가 AI 활용이나 자료 열람이 허용된다고 추정하지 않는다. 작업 문서가 있어도 금지 단계에 열어볼 수 있다는 보장은 없다. 다른 세션을 실제 제어하지 못하면 사용자가 중지할 세션만 짧게 알리고 중지 성공을 꾸미지 않는다.
