# 마무리 — 동작 확인 뒤 사람이 읽을 수 있게

중요한 기능이 끝났거나 제출·최종 검토를 요청했을 때 사용한다. 중간 완료는 해당 범위만 확인한다. 최종 마무리는 아래 순서로 **한 번의 통합 점검**을 하고 필요한 부분만 고친다.

## 1. 실제 요구와 결과

요구한 질문에 답이 있는지, 필수 파일명·위치·형식이 맞는지 확인한다. 파일을 다시 열고 현재 저장된 내용인지 본다. 생성됐다는 말과 실제 파일, 파일 존재와 정확한 내용, 준비 완료와 제출 완료를 구분한다. 미리보기 일부가 제출 전체라고 가정하지 않는다.

| 결과 | 확인할 근거 |
|---|---|
| 데이터 분석 | 대상·기간·분모, 별도 계산 사례, 전후 합계, 결과 파일 |
| 프로그램·자동화 | 실제 입력으로 실행, 중요한 예외, 다시 실행할 방법 |
| 문서·표·그래프 | 핵심 내용과 숫자 일치, 열림, 잘림·단위·제목 |
| 화면·웹 도구 | 허용된 실제 미리보기와 핵심 조작. 실행·정적 확인과 구별 |

최신 변경에 영향받은 검사를 다시 한다. 테스트 0개·모두 건너뜀을 통과로 보고하지 않는다. 기존 검사는 대상 파일·조건이 그대로일 때 기존 근거라고 밝혀 재사용한다. AI가 스스로 동의한 답을 독립 검증이라고 하지 않는다.

## 2. 사용자 입장에서 읽고 다듬기

- 첫 부분만 읽어도 **무엇을 만들었고 무슨 결론인지** 알 수 있는가?
- 이해에 필요한 기본 개념이나 **왜 그 방법을 썼는지**가 빠지지 않았는가? 전문용어를 더 많은 전문용어로 설명하지 않았는가?
- 실제 자료 한 사례가 중요한 처리를 납득하게 하는가? 모든 행·모든 코드의 해설을 붙일 필요는 없다.
- 사용자가 **어떤 파일·항목을 열고 무엇을 보면 되는지** 분명한가? 실제 존재하는 경로만 적었는가?
- 원본·코드·표·문서의 숫자·단위·기간·조건이 일치하고, 유지하기로 한 장점이 남아 있는가?
- 중복 경고, 빈 양식, 과장된 성공 문구, 내용 없는 추상 표현을 줄였는가? 줄이느라 핵심 근거와 한계를 지우지는 않았는가?

시각 자료는 실제 결과가 있어야 한다. 볼 수 없던 화면이나 클릭 성공을 만들어내지 않는다. 손볼 곳이 없으면 다시 쓰지 않는다. 표현만 고쳤으면 무관한 전체 테스트를 반복하지 않고 숫자·의미가 바뀌지 않았는지 확인한다. 코드·계산을 바꾸면 영향받은 검사를 다시 한다.

## 3. 끝내기

최종 전달은 **핵심 결과 → 실제 파일/확인 위치 → 확인한 근거 → 중요한 한계**로 한다. 작성한 설명을 사용자가 이해했다는 증거로 취급하지 않는다. AI가 실행한 일과 사용자가 실제 선택한 일을 구분한다. 검증 실패·미확인은 숨기지 않는다.

필수 결과가 있고 중요한 확인을 통과했다면 종료한다. 마감이 가까우면 치명적 오류·누락 파일부터 처리하고 선택적 꾸미기를 생략한다. 최종 제출·외부 게시 등은 실제 규정과 명시적 권한을 따른다. AI 금지 서술형 단계가 시작되면 질문 생성·설명·답변·첨삭을 중단한다.
