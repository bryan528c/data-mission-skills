# 도구와 모델 — 도움이 되는 것만 선택

기본 도구로 막힌 점이 생기거나 사용자가 선택을 요청했을 때 적용한다. 매 작업마다 스킬 검색부터 하지 않는다. 반대로 새 도구로 실제 시간을 줄일 수 있는데도 무조건 배제하지 않는다.

## 선택 순서

1. 현재 부족한 기능을 한 문장으로 특정한다. 예: 큰 자료를 전부 메모리에 올릴 수 없다 / 특정 버전 함수의 사용법이 필요하다.
2. 제공된 도구·이미 설치된 라이브러리로 해결 가능한지 확인한다. 계산은 실제 코드로, 공식 업무 조건은 과제 원문·담당자 답으로 확인한다. 웹 검색으로 비공개 운영 기준을 알아낼 수 있다고 가정하지 않는다.
3. 필요하면 허용된 검색으로 관련 후보 최대 두 개의 실제 내용·사용조건·라이선스·의존성·설정 부담을 비교한다. 별 수·최근 수정일·스킬 수는 후보 탐색용이지 성능 증거가 아니다.
4. 이점이 구체적이고 허용 범위에 맞으면 현재 승인에 포함되는 작은 작업은 진행한다. 새 설치·계정·외부 전송·큰 설정 변경은 권한과 위험을 확인한다. 사용자에게 도구 메뉴를 떠넘기지 말고 추천안과 이유를 준다.
5. 다운로드, 등록, 연결, 실제 호출을 구분해 확인한다. 실패하면 설치를 계속 늘리지 말고 기본 방법으로 돌아가거나 미해결 한계를 알린다.

## 모델과 추론 강도

실제로 선택 가능한 모델과 현재 설정을 우선한다. 사전체험에서 쓸 만했던 설정은 출발점일 뿐 우월성이 검증된 것은 아니다. 확정된 계산·단순 수정은 현재 설정을 유지하고, 여러 조건이 얽힌 판단·원인 불명 오류에는 더 높은 추론이 필요한지 본다. 이름만으로 속도·품질·평가 점수를 단정하지 않는다.

자료에 답이 없는 정책을 모델 변경으로 해결하려 하지 않는다. 지원 명령과 권한을 확인하지 않고 모델이 바뀌었다고 말하지 않는다. 변경 이유와 실제 이득이 있을 때만 짧게 기록한다. 모든 작업의 상세 사고 과정을 요구하거나 여러 모델로 무의미하게 반복하지 않는다.

## MCP·스킬의 차이와 범위

스킬은 **일하는 방법을 적은 지침**, MCP는 **다른 도구를 호출하는 연결**이다. MCP 서버 코드가 공개돼 있어도 질문·자료가 외부 서버로 전송될 수 있다. 제한된 과제의 원문·코드·값·로그를 외부 검색·문서 조회·변환 서비스에 보내지 않는다. 필요한 경우 공개 라이브러리 이름·일반적인 기능 질문만 전달한다.

파일 읽기·메모는 기존 도구와 작업 파일로 충분하면 MCP를 추가하지 않는다. 제공 환경에서 지원되고 허용된 문서 조회 등 실제로 필요한 연결만 후보로 삼는다. 공개 저장소 설치 스크립트를 읽기 전에 실행하지 않고, 전역 설정·인증·관리 블록·제공 Codex 버전을 바꾸지 않는다. 자동 연결·자동 업데이트·외부 게시를 포함하지 않는다.
