# 제약 배정

## 뜻과 적용

제한된 자원·시간·장소에 대상을 배치하는 작업이다. “규칙을 지키는 안”과 “그중 더 좋은 안”, “최적임을 증명한 안”은 다르다. 사람·좌석·작업·장비·이동 중 실제 배정 대상부터 확인한다.

## 먼저 확인

대상 전체와 실제 수요가 같은가? 용량·시간·고정 위치·중복 배정·이동 정보의 기준은 무엇인가? 반드시 지킬 조건과 개선 목표를 나눈다. 오래된 계획은 현재 자료로 평가할 비교 기준일 수 있지만 정답으로 고정하지 않는다. 거리와 소요시간, 직선거리와 실제 도로정보를 혼동하지 않는다. 민감한 위치정보를 허용되지 않은 외부 서비스에 보내지 않는다.

## 작은 첫 결과와 구조

입력 검사 → 생성기 → 별도 제약 검사기 → 결과·미배정·위반 사유 → 필요한 저장·조회 순으로 작은 사례부터 연결한다. 간단한 방법으로 가능한 안을 만든 뒤 실제 필요에 따라 개선한다. 특정 최적화 도구를 먼저 설치하거나 화면 지도부터 만들지 않는다.

검사기는 생성기가 성공했다고 반환한 값과 별개로 현재 규칙을 적용한다. 사람이 수정한 계획·재계산 결과에도 같은 검사를 적용한다. 입력·설정이 바뀌면 이전 계획을 최신인 척 표시하지 않는다. 화면·저장·내보내기는 같은 확정 상태를 읽도록 설계한다.

## 검증할 위험

대상 누락·중복, 용량 초과, 시간 순서·마감 위반, 참조 ID 누락, 경계값, 빈 수요, 재계산 후 변경 반영, 같은 결과의 조회·내보내기 일치를 검사한다. 총합만 맞아도 각 대상이 잘못 연결될 수 있다.

**탐색 시간 초과·현재 방법 실패와 조건상 불가능을 구분한다.** 작은 독립 예에서 총 용량이 수요보다 작으면 그 조건에서 부족함을 설명할 수 있지만, 경로 탐색에 실패했다는 이유로 해가 없다고 증명한 것은 아니다. 필수 조건을 조용히 풀거나 미배정 대상을 삭제하지 않는다. 현재 방법, 중단 조건, 남은 대상을 보고한다.

## 실무자 질문과 설명

“모든 조건을 만족하지 못할 때 무엇을 조정할 권한이 있고 어떤 결과를 보류해야 하나?”를 구체적인 사례로 묻는다. 임시 기준은 사용자 선택과 영향을 남기고 변경 가능하게 둔다.
설명은 **입력 단위 → 생성 방식 → 독립 검사 → 실패 처리 → 수정·재계산·저장**을 실제 함수로 연결한다. 성능·최적성·실제 이동시간을 측정하지 않고 주장하지 않는다.
