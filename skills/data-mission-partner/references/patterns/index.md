# 업무 유형 선택 — 한 번에 필요한 부분만

이 목록은 공개적으로 재사용할 업무 패턴이다. 특정 시험의 원문·정답·출제 목록이 아니다. 실제 지시서·자료·제출 양식을 먼저 읽고, **사용자가 하려는 행동과 필요한 결과**로 선택한다. ID·파일 이름·예상 주제만으로 기능을 확정하지 않는다.

| 실제 작업 | 먼저 읽을 지침 | 작은 첫 결과 |
| --- | --- | --- |
| 시장·실적·지표를 같은 기준으로 비교 | [비교 분석](comparison.md) | 같은 기간·단위의 비교 한 묶음과 근거 |
| 소재·공급처·대안의 변경 여부 검토 | [변경 검토](change-review.md) | 필수 조건·부족한 근거가 보이는 후보 비교 |
| 제한된 용량·시간에 사람·작업·이동 배정 | [제약 배정](allocation.md) | 생성안과 별도 조건 검사 |
| 기간별 편성과 선호·관심을 함께 관리 | [일정과 선호](schedule-preference.md) | 작은 일정과 제약·관심 지표의 구분 |
| 공간의 후보 위치·설치안을 비교 | [공간 검토](spatial-review.md) | 후보별 목표·범위·근거 부족 표시 |
| 측정 품질·오차·장비 상태를 판단 | [측정 품질](measurement-quality.md) | 한 대상의 측정→판정→근거 연결 |
| 기업·제품·공정·산업 관계와 영향을 분석 | [관계와 영향](relationship-impact.md) | 근거 있는 관계 한 경로와 시나리오 |
| 대상자의 수준에 맞춰 설명·교육 제작 | [설명과 교육](learning-content.md) | 한 개념·사례·전이 확인의 완성된 학습 |

복합 업무는 주된 결과의 유형을 먼저 읽고 실제 필요한 부분만 덧붙인다. 웹 화면은 모든 유형에 필수인 별도 결과가 아니다. 첫 데이터 흐름과 사용자의 주요 행동을 정한 다음 필요한 화면을 구현한다. 어느 유형에도 맞지 않으면 [다른 업무와 공통 분해](other-work.md)를 참고하거나 실제 요구로 새롭게 분해한다. 기존 틀에 억지로 끼우지 않는다.

각 문서의 질문은 점검 후보다. 자료에 답이 있으면 다시 묻지 않고, 실제로 결과를 바꿀 질문만 선택한다. 모든 항목을 필수 기능·필수 문서로 만드는 것은 금지한다. 구현 예시의 파일명·규칙은 실제로 확인한 값으로 바꾼다. 도구 설치·모델·알고리즘·기술 스택은 고정하지 않는다.
