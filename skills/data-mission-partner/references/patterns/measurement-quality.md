# 측정 품질

## 뜻과 적용

측정값을 올바른 단위·기준·대상과 연결해 이상 여부와 확인할 근거를 보여주는 작업이다. 이상이 관찰됐다는 것과 고장 원인이 밝혀졌다는 것은 다르다.

## 먼저 확인

한 행이 측정 지점·제품·로트·장비·이벤트 중 무엇인지, 축·부호·단위·측정 시점·보정 전후·중복 재측정·기준의 시행일을 읽는다. 합격 규격과 데이터로 계산하는 통계적 관리 한계를 혼동하지 않는다. 축별 오차와 벡터 크기는 정의가 다르므로 원문 기준 없이 계산식을 바꾸지 않는다. 장비·공정별 다른 기준을 전체 하나로 덮지 않는다.

## 작은 첫 결과와 구조

입력 검사 → 적용 기준 연결 → 측정/추이 계산 → 판정과 근거 → 조사할 대상 표시로 작은 대상 하나를 완성한다. 기준이 없으면 “정상”이 아니라 “판정 기준 확인 필요”로 둔다. 실측·통계적 신호·가능한 원인·조치 제안을 분리한다. 임계값을 통과하게 하려고 원자료나 판정 기준을 바꾸지 않는다.

화면은 이상 목록·대상별 상세·시간 변화와 근거부터 고려한다. AI 설명은 검산한 값과 확인된 문서에 근거하고, 장비 자동 제어·원격 변경은 명시된 권한 없이는 수행하지 않는다.

## 검증할 위험

단위 변환, 양·음 오차 상쇄, 경계 포함 여부, 기준 누락, 같은 대상의 재측정, 작은 표본·기간 혼합을 확인한다. 평균이 양호해도 일부 큰 오차가 숨을 수 있으므로 요구된 지표와 해당 사례를 본다. 특이값은 바로 삭제하지 않고 유효성·영향을 확인한다. 모델 학습이 요구되지 않으면 예측 모델부터 만들지 않는다.

## 실무자 질문과 설명

“지금 필요한 것은 합격 판정, 조사 우선순위, 원인 후보, 운영 조치 중 무엇인가?”와 적용 기준의 근거를 묻는다. 기준이 불충분하면 사실 표시와 추가 확인으로 범위를 제한한다.
설명은 **측정 단위 → 기준 매칭 → 계산/판정 함수 → 경계·누락 검증 → 원인·운영 한계**로 한다. 상관을 인과로, 테스트 한 건을 전체 장비의 안전성 검증으로 바꾸지 않는다.
