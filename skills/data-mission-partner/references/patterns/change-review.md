# 변경 검토

## 뜻과 적용

새 대안이 싸거나 좋아 보이는지뿐 아니라, 바꾸어도 되는 근거와 남은 위험을 확인하는 작업이다. 추천과 승인·실제 전환 실행은 다르다.

## 먼저 확인

현행 기준, 후보의 검증자료, 반드시 충족할 조건, 비교 가능한 비용 단위·기간, 품질·납기·호환·중단 영향 중 실제 요구된 범위를 읽는다. 검증 완료·실패·미검증을 나눈다. 승인권자와 추가 확인이 필요한 단계를 확인한다. 모든 항목을 임의 점수로 합쳐 순위를 만들지 않는다.

## 작은 첫 결과와 구조

자료 읽기 → 필수 조건 확인 → 비교 가능한 속성 표시 → 근거·미확인·추천 사유로 연결한다. 필수 조건 실패가 가격 장점으로 상쇄되지 않게 한다. 임시 가중치를 쓰기로 승인받았다면 가정과 가중치 변경의 영향을 보이게 한다. 근거 없는 항목에 0점·합격을 주지 않는다.

화면이 필요하면 후보 비교표와 근거 상세, 검토 상태부터 만든다. 승인 기능·업로드·알림은 실제 요구일 때만 구현한다. 상태를 바꿀 권한과 필수 근거 검사를 화면·서버 중 실제 어디에 구현했는지 구분한다.

## 검증할 위험

단위가 다른 가격, 누락된 시험자료, 승인 전 변경, 버전이 다른 규격, 필수 조건 실패, 동률·보류 사례를 검사한다. 후보 정보 수정 후 이전 추천을 최신으로 보이지 않게 한다. 총점이 같아도 위험이 같다는 뜻이 아니다. 원본 시험값을 추천에 맞춰 수정하지 않는다.

## 실무자 질문과 설명

“부족한 근거를 확보하기 전에는 보류인가, 조건부 검토가 가능한가?”처럼 실제 누락과 결과를 연결해 묻는다. 불명확하면 가능한 비교는 진행하되 최종 승인으로 표시하지 않는다.
설명은 **필수 조건과 선호를 나눈 이유 → 판정 위치 → 선택하지 않은 대안 → 검증·추가 확인**으로 한다. 안전성이나 품질 보증을 확인 없이 주장하지 않는다.
