# 일정과 선호

## 뜻과 적용

일정 편성은 조건을 지키며 날짜·슬롯에 대상을 놓는 일이고, 관심 분석은 어떤 대상에 반응이 있었는지 보는 일이다. 클릭·좋아요·설문 응답이 실제 이용·구매·섭취를 뜻하지는 않는다. 두 흐름을 처음부터 같은 값으로 합치지 않는다.

## 먼저 확인

기간·영업일·슬롯, 대상 목록, 중복/반복·공급·비용 등 실제 편성 조건, 관심 기록의 분모·노출·중복·시점을 확인한다. 식품·건강 관련 제약이 있으면 제공된 검증된 기준만 적용하고 영양·알레르기 안전 기준을 추측하지 않는다. 개인 기호와 안전상 금지를 서로 상쇄시키지 않는다.

## 작은 첫 결과와 구조

편성 자료·조건 확인 → 작은 기간의 일정 → 별도 제약 검사 → 수정·저장으로 이어간다. 관심 기록은 별도 집계해 추천의 참고 근거로 연결한다. 자동 추천·자동 편성·관리자 확정의 범위를 나눈다. 필요한 경우 달력/표, 선택한 항목의 조건, 오류·편성 불가 사유부터 보여준다.

## 검증할 위험

쉬는 날·없는 날짜, 빈 슬롯·겹친 배정, 같은 대상의 금지된 반복, 공급 불가, 비용 단위, 미확인 안전정보, 노출량이 다른 항목의 단순 인기 비교를 점검한다. 설정을 바꾼 뒤 일정과 추천이 함께 최신화됐는지 본다. 제약 충돌 시 어떤 조건 때문인지 설명하고 임의 완화하지 않는다.

## 실무자 질문과 설명

“관심 지표는 편성을 결정하는 기준인가 참고 정보인가?”, “예외 편성은 누가 확정하는가?”를 실제 자료에 연결한다. 분명한 답이 없으면 관심 현황과 실행 가능한 편성안을 분리한다.
설명은 **편성 기준과 관심 근거의 차이 → 어떤 조건을 코드로 검사했나 → 수동 수정 후 검사는 어떻게 하나 → 미확인 정보의 처리**다. 같은 데이터가 생성·검사에 재사용돼도 검사 기대값은 독립적으로 확인한다.
