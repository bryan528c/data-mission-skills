# 다른 업무와 공통 분해

앞의 여덟 유형은 출제 예측이나 적용 가능한 모든 업무의 목록이 아니다. 맞지 않으면 실제 사용자·입력·판단·상태·결과·검증으로 분해한다. 자료에 없는 정책·필수 기능을 만들지 않는다.

| 다른 작업 | 우선 분해 | 특히 조심할 것 |
| --- | --- | --- |
| 고객 문의·운영 지원 | 문의 분류 → 적용 정책 → 답/담당자 연결 → 미해결 표시 | 정책에 없는 보상 약속, 추측 답변, 개인정보 노출 |
| QA·품질 확인 | 기대 동작 → 재현 입력 → 실제 차이 → 수정·재검사 | 테스트 건수만 제시, 재현하지 않은 오류 단정 |
| 인터뷰·미디어 준비 | 대상·목적 → 검증된 사실 → 질문 흐름 → 승인할 내용 | 인물의 발언·의도 창작, 자료의 확인 수준 혼동 |
| 행사·프로그램 운영 | 대상·일정·정원·업무 책임 → 신청/상태·안내 | 승인 없는 외부 발송, 확정 전 일정·혜택 약속 |
| 비용·승인·민감 거래 검토 | 금액/상태 → 원문 정책 → 증거 → 검토·보류 | 자동 승인·송금·차단, 미확인 근거를 정상으로 간주 |
| 게임·상호작용 시제품 | 플레이 흐름 → 상태 전환·규칙 → 최소 한 판/반복 → 동작 확인 | 요구 없는 대형 콘텐츠, 규칙과 표시 불일치, 리소스 권리 누락 |

계산·규칙·출처는 [데이터 확인](../data-checks.md), 오류는 [오류 해결](../debugging.md)을 재사용한다. 해당 업무가 정보 제공인지 실제 외부 조치인지 구분한다. 승인이 필요한 행동은 현재 권한을 확인한다. 간단한 작업에 여러 패턴과 문서를 강제하지 않는다.
