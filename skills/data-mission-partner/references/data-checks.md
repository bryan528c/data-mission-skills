# 데이터 확인 — 계산 전에 뜻부터

결과를 바꿀 위험에 맞춰 검사한다. **많이 검사했다는 수치보다, 이 결과를 믿어도 되는 이유**가 중요하다. 모든 과제에 모델 학습이나 전체 데이터 감사를 적용하지 않는다.

## 1. 무엇을 세고 있는가

- 한 행이 주문·주문 품목·배송 이벤트·측정 중 무엇인지 확인한다. 같은 ID가 여러 번 있다는 이유만으로 삭제하지 않는다.
- 분석 대상, 포함·제외 조건, 기간 양 끝, 시간대, 금액·수량 단위를 확인한다. 문서는 승인·시행일·적용 대상·대체 관계를 본다. 최신 작성일만으로 선택하지 않는다.
- 비율은 분자와 분모를 확인한다. 집단 크기가 다르면 비율의 단순 평균과 전체 비율은 다르다. 전체 분자와 분모를 각각 합산해야 하는지 원문 규칙으로 정한다.
- 업무 기준에 답이 없으면 담당자 확인 대상으로 분리한다. 빈 값을 0으로 바꾸거나 이상치를 제거해도 된다고 임의로 정하지 않는다.

## 2. 자료를 실제로 읽는다

파일 형식·크기·열 이름·자료형·행 수·결측·중복·기간·값 범위를 필요한 만큼 확인한다. 큰 파일은 우선 구조·일부 행을 보고, 전체 검사는 코드나 기존 로컬 도구로 처리한다. 전체 원문을 채팅에 출력하지 않는다. 일부 표본을 본 것과 전체를 검사한 것을 구분한다.

CSV·JSON은 번호의 앞자리 0과 숫자/문자 구분을 확인한다. Excel은 필요한 시트·수식/계산값, PDF·문서는 표와 조건의 추출 누락을 확인한다. 텍스트 추출 실패를 빈 문서로 단정하지 않는다. 확인할 도구가 없으면 미확인으로 남기고 과제 자료를 외부 변환 서비스로 보내지 않는다.

## 3. 바꾸고 연결한 뒤 다시 본다

원본을 보존한다. 제외·변환 기준과 건수를 재현 가능하게 남긴다. 연결할 양쪽 번호가 몇 번씩 나타나는지 확인한다. 한 주문에 여러 배송이 있으면 행이 늘어날 수 있으므로, 먼저 어떤 단위로 합쳐야 하는지 판단한다.

처리 전후 행 수·고유 대상 수·연결되지 않은 항목·핵심 합계를 확인한다. 값은 계산 정밀도를 유지하고 표시에만 반올림한다. 0 분모·빈 그룹·작은 분모는 별도로 처리한다. 표가 이미 요약된 자료라면 없는 개별 원본까지 대조했다고 하지 않는다.

## 4. 기대값을 별도로 만든다

일반 사례, 정확히 기준과 같은 값, 누락·0·중복 등 결과를 바꿀 사례를 고른다. 원문 규칙으로 예상값을 먼저 구하고 실제 결과와 비교한다. 같은 함수를 다시 호출한 결과를 독립 검산이라고 하지 않는다. 전체와 부분 합계 등 다른 간단한 기준도 활용한다.

설명용 예: 100개 중 불량 2개와 900개 중 불량 36개면 전체는 38/1000=3.8%다. 2%와 4%의 단순 평균 3%가 아니다. 실제 과제에는 실제 자료와 규칙을 쓴다.

결론은 **확인한 사실 → 가능한 의미 → 제안 행동 → 중요한 한계**로 연결한다. 연관성이 있다는 이유로 원인이라고 단정하지 않는다. 그래프·보고서·결과 파일은 같은 계산과 기간·단위를 사용한다.

## 예측 문제일 때만

평가지표와 시간·사람·설비별 분리 기준을 확인한다. 예측 시점 이후 정보가 들어가지 않았는지, 학습 자료로만 정할 처리를 평가 자료에 미리 맞추지 않았는지 본다. 간단한 기준 방법과 비교하고 실제 개선이 있을 때 복잡도를 높인다. 불균형 데이터에서는 정확도 하나만 믿지 않되 그 지표 자체를 일률적으로 금지하지 않는다. 실행하지 않은 학습·평가 수치는 만들지 않는다.
