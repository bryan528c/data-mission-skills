# 데이터 확인 기준

수치나 데이터 해석이 결과를 좌우할 때 읽는다. 모든 항목을 기계적으로 수행하지 말고 결론을 바꿀 위험부터 확인한다.

## 계산 전에 기준을 고정한다

1. **한 행의 의미**: 사람, 주문, 주문 품목, 이벤트, 측정값 중 무엇인가? 고유 키와 중복의 의미를 확인한다. 중복처럼 보인다는 이유만으로 삭제하지 않는다.
2. **대상과 범위**: 분석 대상, 포함·제외 조건, 기간의 시작·끝, 시간대, 단위를 확인한다. 취소·환불·실패·재처리 기록을 어떻게 반영할지 정의한다.
3. **지표의 정의**: 분자·분모, 합계·평균·비율, 건수·고유 수를 구분한다. 집단별 비율의 평균과 전체 비율이 다를 수 있으므로 원래 분모로 재집계한다.
4. **자료의 상태**: 파일을 실제로 열어 열 이름, 자료형, 행 수, 결측, 값 범위, 날짜 형식을 확인한다. 일부 표본으로 본 범위와 전체 검사 범위를 구분한다.

## 변환과 결합을 확인한다

- 결측을 0으로 바꾸거나 이상치를 제거하면 의미와 결과가 달라지는지 확인한다. 원본은 유지하고 적용 기준과 제외 건수를 남긴다.
- 결합 전 양쪽 키의 고유성을 확인한다. 일대다·다대다 관계가 행을 늘리는 경우 합계가 부풀 수 있으므로 필요한 단위로 먼저 집계하거나 관계를 명시한다.
- 결합 후 행 수, 고유 대상 수, 미결합 건수, 핵심 합계를 확인한다. 행 수 증가가 오류인지 정상인지 데이터의 의미로 판단한다.
- 금액·비율·수량은 단위를 붙인다. 계산 정밀도와 표시용 반올림을 구분한다. 작은 분모나 빈 그룹은 과장하지 않는다.

## 핵심 결과를 교차 확인한다

- 원본의 소수 사례를 직접 계산해 코드 결과와 비교한다. 전체와 부분 합계, 전후 행 수 등 별도의 간단한 기준으로도 확인한다.
- 데이터가 이미 집계되어 있으면 원자료에서 확인할 수 있는 것처럼 표현하지 않는다. 누락된 기간·집단의 대표성을 가정하지 않는다.
- 추천은 “발견한 사실 → 가능한 의미 → 제안하는 행동 → 확인이 필요한 조건”으로 연결한다. 단순 상관을 원인으로 단정하지 않는다.
- 그래프는 실제 결과를 사용하고 축·단위·범례·대상 기간을 확인한다. 그림과 본문 수치가 같은 계산에서 나오는지 확인한다.

## 예측 과제인 경우에만 추가한다

- 평가 지표와 데이터 분할을 문제 요구에 맞춘다. 시간·개인·장비 등이 양쪽 집합에 섞여 답을 미리 알게 되는 정보 누출을 확인한다.
- 학습에만 사용해야 하는 전처리를 평가 데이터에 미리 맞추지 않는다. 간단한 기준 모델부터 측정하고 실제 평가 결과로 개선을 판단한다.
- 실행하지 않은 학습이나 평가 수치를 제시하지 않는다. 과제의 비교 조건이 다른 점수는 직접적인 우열로 표현하지 않는다.
