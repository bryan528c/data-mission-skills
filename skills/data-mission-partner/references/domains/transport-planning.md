# 통근·노선·배정 계획

일반 업무 지침이다. 특정 시험의 실제 데이터·정답·운영 규칙을 담지 않는다.

## 먼저 이해할 말

**제약**은 반드시 지킬 조건이고 **목표**는 그 안에서 더 좋게 만들 항목이다. **생성기**는 계획을 제안하고 **검사기**는 그 계획이 조건을 지키는지 확인한다. 최단거리만 구했다고 이용 가능한 계획이 되는 것은 아니다.

## 확인할 질문과 자료

한 행이 사람·신청·가구·정류장 수요 중 무엇인지, 거주 인원과 이용 대상이 같은지, 후보 정류장과 신설 허용 범위, 차량별 정원·운행 횟수·시간 조건, 이동시간 근거, 배정 대상·우선순위·필수 출력이 무엇인지 확인한다. 기존 노선과 현재 수요의 기준 시점도 구분한다.

## 작은 첫 결과와 분업

작은 수요로 **입력 → 실행 가능한 기본 배정 → 별도 조건 검사 → 실제 결과 조회**를 만든 뒤 전체로 확대한다. A는 자료·규칙·생성·검사, B는 합의한 입력/출력의 조건 변경·목록·상세·내보내기를 맡을 수 있다. 역할별 조회가 필요하면 화면 구분과 실제 접근 통제를 구별한다. 외부 지도 서비스는 필수가 아니다.

## 놓치기 쉬운 검사

- 누락·중복 배정, 정원, 참조하지 않는 ID, 시간 순서·시간대, 명시된 도착 조건을 검증한다.
- 차량 두 대의 총정원만 보지 말고 개별 노선·운행·승하차 구간의 용량도 실제 규칙에 맞게 확인한다.
- 미배정은 대상과 사유를 남기며 성공 결과에서 조용히 빼지 않는다.
- “방법이 못 찾음”, “시간 안에 탐색 못 마침”, “조건상 불가능”, “최적성 확인”을 구분한다. 탐색 실패가 불가능의 증명은 아니다.
- 직선거리와 도로시간, 추정시간과 제공된 측정시간을 구분한다. 제한된 주소·좌표를 외부 API에 보내지 않는다.
- 수정·재계산 후 현재 설정, 화면, 저장, 내보내기가 같은 버전을 사용해야 한다. 규칙을 바꾸어 실패를 숨기지 않는다.
- 기존안과 새안을 같은 현재 수요·지표로 비교한다. 다른 대상이나 기준으로 개선율을 만들지 않는다.

## 한 사례로 설명

가상 조건: 40석 차량 두 대가 동시에 한 번만 운행하고 대상85명을 모두 태워야 한다. 총80석이므로 적어도5석 부족하다. 하지만 재운행이 허용되면 이 결론은 달라진다. 개별 배정법이5명을 남겼다는 사실만으로는 동일한 불가능을 증명하지 못한다.

## 설명 준비

어떤 함수가 생성하고 검사하는지, 조건을 어디서 받는지, 재계산 때 이전 결과를 어떻게 다루는지, 누락된 대상의 사유와 방법의 한계를 실제 코드로 설명한다.

공개 배경: [OR-Tools 차량 경로](https://developers.google.com/optimization/routing), [탐색 상태](https://developers.google.com/optimization/routing/routing_options). 도구 설치를 요구하지 않으며 정확한 상태 구분의 참고다.

## 심화 실무: 데이터 모델·구현·검증

**입력·상태 설계:** 수요(신청자 또는 정류장별 집계·기준시점), 정류장(ID·위치·가용여부), 차량(운행별 정원·가용시각), 노선·운행(정류장 순서·시간), 배정(대상→운행), 계획(ID·버전·상태), 미배정/위반(대상·조건·사유)으로 구분한다. 전체 거주자와 실제 이용 신청자를 동일하게 취급하지 않는다.

**작동하는 첫 결과:** 입력 검증 → 작은 수요로 가능한 기본 계획 생성 → 생성 로직과 별개인 제약 검사 → 결과·미배정 사유 표시 → 수동 수정·재계산 → 조회·저장·JSON 내보내기. A는 생성·검사·공통 계약, B는 합의된 결과의 조작·표시·출력을 맡을 수 있다. 입력/출력 버전과 상태를 함께 둔다.

**계산·판단 규칙:** 용량은 총인원뿐 아니라 실제 조건에 따라 차량·운행·승하차 구간에서 확인한다. 시간표는 주어진 이동시간·정차·도착 마감에 따른다. 직선거리를 실제 주행시간이라고 주장하지 않는다. 휴리스틱의 탐색 실패·시간초과는 해가 없다는 증명이 아니며 최적성도 별도 증명이다. 과거와 신규 계획은 같은 현재 수요/제약으로 비교한다.

**검증 시나리오:** 수요0, 차량 정원과 같은 값·초과 1명, 누락·중복 대상, 존재하지 않는 정류장 ID, 음수 이동시간·도착 마감 위반, 구간별 점유 초과, 규칙 변경 뒤 구버전 계획 노출, 화면·저장·내보내기 값 불일치.

**설명용 가상 사례:** 가상 4석 차량에서 첫 정류장 3명과 다음 정류장 2명이 타고 모두 종점에서 내리면 다음 구간에 5명이 탑승해 정원을 초과한다. 두 번째 정류장 전에 하차가 있다면 상황이 다르다. 제공되지 않은 하차를 임의 가정해서는 안 된다.

**실무자 상호작용과 서술형 대비:** 실제 배정 단위·목표와 필수 제약의 우선순위, 생성/검사 함수 구분, 미배정과 실패 처리, 재계산·저장·JSON 동일 계획 확인, 직접 실행한 예외를 코드 기준으로 설명한다.
