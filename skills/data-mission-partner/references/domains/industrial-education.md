# 산업 개념과 교육 도구

일반 업무 지침이다. 설명 자료를 많이 모으는 것과 학습이 일어나는 것을 구분한다.

## 먼저 이해할 말

**학습목표**는 읽고 난 뒤 학습자가 할 수 있어야 하는 행동이다. **선행 개념**은 그 내용을 이해하기 전에 알아야 할 뜻이다. 예를 들어 산업의 기업 역할을 비교하려면 먼저 설계·제조·패키징/시험이 무엇인지 알아야 한다.

## 확인할 질문과 자료

학습자의 사전 지식·언어·사용 시간, 필수 주제, 학습목표, 제공 자료의 범위·시점, 실제 결과물(설명서·웹 학습·퀴즈·발표 등)을 확인한다. 모르는 대상 수준을 전문가로 가정하지 않는다. 공개 지식 보완이 필요하면 공식 출처를 확인한다.

## 작은 첫 결과와 분업

핵심 개념 하나를 **쉬운 뜻 → 구체적 예 → 산업 안의 연결 → 확인 질문과 근거 있는 해설**로 완성하고 필요한 주제로 확장한다. A는 사실·선행 개념·학습목표·정답 근거, B는 탐색·학습 화면·상호작용·저장 등 요구된 전달 방식을 맡는다. 영상·캐릭터·복잡한 추천 엔진은 자동 추가하지 않는다.

## 놓치기 쉬운 검사

- 용어 정의만 나열하지 않는다. 목표가 관계 설명이라면 사실 암기 문제만으로 달성했다고 판단하지 않는다.
- 팹리스·파운드리·IDM·조립/시험 등 역할을 기본 정의부터 설명하되, 모든 기업이 하나의 역할만 한다고 가정하지 않는다.
- 비유는 도움이 되는 범위와 차이를 밝혀 사실과 섞지 않는다. 원문에 없는 세부 공정·시장 수치를 생성하지 않는다.
- 문제의 정답·해설·본문이 일치해야 한다. 여러 답이 가능한 질문에 단일 정답을 강제하지 않는다.
- 페이지 방문·완료 체크는 이해·장기 기억을 증명하지 않는다. 측정하지 않은 교육 효과를 주장하지 않는다.
- 진행 저장·초기화가 요구되면 실제 저장 범위와 유지 여부를 확인한다. 설명 자료만 요구했는데 계정·DB부터 만들지 않는다.

## 한 사례로 설명

학습목표가 “설계 전담과 제조 전담의 관계를 설명한다”인데 평가가 약어 뜻 맞히기뿐이면 관계를 이해했는지는 확인하기 어렵다. 가상 제품이 어떤 역할을 거치는지 설명하는 작은 활동을 추가하고, 설명의 근거를 본문과 연결할 수 있다.

## 설명 준비

학습자 수준을 어떻게 반영했는지, 어떤 선행 개념을 먼저 설명했는지, 각 확인 활동이 어느 목표를 확인하는지, 실제로 관찰한 학습 결과와 아직 모르는 효과를 구분한다.

공개 배경: [CMU 목표·학습·평가의 정렬](https://www.cmu.edu/teaching/assessment/basics/alignment.html), [SIA 생산 과정](https://www.semiconductors.org/semiconductors-101/how-are-semiconductors-made/). 특정 수업·대회의 정답과 교육 효과를 보증하지 않는다.

## 심화 실무: 데이터 모델·구현·검증

**입력·상태 설계:** 학습 대상·선행지식, 학습 목표(설명·비교·적용 같은 행동), 개념과 선행관계, 검증된 근거, 단원·예시·퀴즈·해설, 실제 요구된 경우에만 진행 저장을 분리한다. 방문/완료 체크와 실제 이해 증거는 다르다.

**작동하는 첫 결과:** 학습 목표 한 개 → 필요한 기초 뜻 → 근거 있는 사례 → 새 사례에 적용 → 정답·해설이 맞는 확인 활동의 한 흐름을 완성한다. 이후 범위를 확대한다. A는 내용·근거·난이도·평가 기준, B는 요청된 화면·탐색을 맡는다. 문서만 요구하면 별도 웹앱을 만들지 않는다.

**계산·판단 규칙:** 초보자에게 전문 용어를 다른 미설명 용어로 설명하지 않는다. ‘관계를 설명한다’는 목표를 약어 암기만으로 평가하지 않는다. 제조·설계·패키징 역할을 한 회사에 하나씩만 고정하지 않는다. AI 생성이 아닌 정적 콘텐츠를 생성형 AI라고 속이지 않는다.

**검증 시나리오:** 사전 정의 없는 전문용어, 출처 없는 시장/기업 수치, 내용과 퀴즈 정답·해설 불일치, 복수 정답 가능성, 비유와 실제 사실의 혼동, 저장·초기화의 동작과 설명 불일치, 학습효과의 과장.

**설명용 가상 사례:** 가상 학습 목표가 ‘설계 기업과 제조 기업이 어떻게 협력하는지 설명’인데 평가가 약어 뜻 맞히기뿐이라면, 새 제품의 설계·제조 역할을 구분하는 활동을 추가할 필요가 있다.

**실무자 상호작용과 서술형 대비:** 왜 이 순서·난이도인지, 원문과 보충자료의 경계, 교육 결과물의 근거, 학습 확인의 실제 범위와 미검증 효과를 설명한다.

### 단계별로 실제 작업을 끊어 진행하기

① 대상 수준과 학습 후 해야 할 행동을 정한다. ② 필요한 선행 개념을 순서대로 배치한다. ③ 설명·원문 근거·가상 사례를 구분한다. ④ 새 사례 적용 질문과 해설을 만든다. ⑤ 실제로 관찰한 학습 활동과 아직 미측정인 학습 효과를 분리한다.

### 구현 상태·데이터 연결 계약

학습 목표와 단원·개념·문항·정답 근거가 서로 연결돼야 한다. 등록·개인화·영상·AI 생성 기능은 실제 요구될 때만 넣는다. 정적 콘텐츠를 실시간 AI 기능이라 소개하지 않는다.

### 합격 판정 대신 실제로 확인할 것

설명 전에 등장하는 미정의 용어, 사실/비유 혼용, 본문과 정답 불일치, 복수 정답을 허용해야 하는 문제, 목표가 관계 이해인데 암기만 평가하는 문항, 실제 저장 상태를 검증한다.

### 업무 담당자에게 제안할 질문 방향

학습자가 모르는 용어와 목표를 확인하고, 이해 확인을 주관식·적용 사례로 할지 실제 시간·난도를 함께 조율한다.
