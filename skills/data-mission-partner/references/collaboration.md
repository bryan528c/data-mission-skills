# 이해와 확인 안내

뜻·이유·파일 역할·사용 방법을 묻거나, 다음 판단에 낯선 개념이 필요할 때 읽는다. 모든 작업에 기초 강의를 붙이지 않는다.

## 설명을 행동에 연결한다

질문에 먼저 답한다. **쉬운 뜻 → 현재 자료의 작은 예 → 필요한 이유 → 확인할 곳과 다음 행동**을 연결한다. 전문 용어는 뜻 뒤에 필요할 때 이름을 붙인다. 문서 목차·자료 목록·짧은 전문용어 나열로 이해를 대신하지 않는다.

예: “분모는 비율의 기준이 되는 전체 수예요. 주문 10건 중 취소 2건을 분모에서 빼는지에 따라 결과가 달라져요. 제공 문서의 취소 규칙을 확인한 뒤 같은 기준으로 계산하겠습니다.” 이 수치는 설명용 예이며 실제 자료와 섞지 않는다.

실제 값이면 경로·행/항목을 밝힌다. 짧게 말해도 결과를 바꾸는 조건·단위·불확실성은 남긴다. 이미 아는 내용은 반복하지 않고 새로 바뀐 점에 집중한다. 이해도 연습은 사용자가 요청했을 때만, 짧은 설명 한 건으로 한다. 답을 기다리며 관계없는 구현을 중단하지 않는다.

| 말 | 먼저 설명할 뜻 |
| --- | --- |
| 한 행의 단위 | 표 한 줄이 사람·주문·이벤트·측정 중 무엇을 뜻하는지 |
| 연결·조인 | 같은 번호로 표를 붙이는 일. 한쪽이 여러 줄이면 금액도 반복될 수 있음 |
| 검증 | 미리 정한 예상과 실제 결과를 비교하는 일 |
| 예외 처리 | 잘못되거나 부족한 입력에서 멈춤·보류·설명 중 무엇을 할지 정함 |

## 실무자가 명확히 답하지 않는 경우

1. 원문·자료에 답이 있는지 먼저 확인한다. 이미 받은 답을 반복해서 묻지 않는다.
2. “어떻게 할까요” 대신 실제 확인한 사례와 선택지를 묻는다. 답이 달라지면 결과가 무엇이 바뀌는지 짧게 설명한다.
3. 여전히 모호하면 **확정 사실 / 담당자 의견 / 열린 질문 / AI 제안 / 사용자 선택**을 분리한다. 침묵·“적절히”를 합의로 바꾸지 않는다. 부정·조건·예외를 지운 요약을 만들지 않는다.
4. 결과에 중요한 미확정 기준은 영향과 추천안을 제시한다. 권한 있는 사용자가 임시 기준을 선택하면 가정임을 표시하고 수정 가능한 위치에 둔다. 안전·개인정보·승인 등 필수 조건은 임의 완화하지 않는다.
5. 답 없이도 가능한 원본 파악·확정 기능·검사는 계속한다. 같은 모호한 질문을 무한 반복하지 않고 미확정 부분만 분리한다.

질문 횟수나 거절 기록을 채우려고 같은 질문을 늘리거나 AI 제안을 일부러 거절하게 하지 않는다. 실제로 필요한 판단과 근거만 남긴다.

실무자 대화는 현재 세션에서 실제 접근할 수 있거나 사용자가 전달한 범위만 기록한다. 모든 Codex가 DMs를 자동으로 본다고 가정하지 않는다. 사용자 전달 내용이면 그 사실을 밝힌다. 중요한 결정에는 **받은 답 → 선택 이유 → 반영한 코드/결과 → 검증**을 연결하고 기존 지정 문서를 우선한다. 새 결정으로 바뀐 이전 기준은 조용히 지우지 말고 대체 관계를 짧게 남긴다.

## 파일과 화면의 기본 개념

실제 경로를 **지시서·원본 / 수정할 프로그램 / 확인할 결과**로 구분한다. 역할을 설명하려고 기존 폴더를 옮기거나 이름을 바꾸지 않는다. 같은 역할은 기존 파일을 수정하고 새 역할이 생길 때만 추가한다.

편집기에 열린 파일과 터미널의 현재 폴더는 별개다. 파일 클릭은 보기이며 실행이 아니다. 저장 전 내용은 디스크를 읽는 AI에게 보이지 않을 수 있다. 같은 파일을 동시에 저장하지 말고 충돌하면 양쪽 변경을 확인한다. 저장·로컬 Git Commit·Push·플랫폼 제출은 서로 다르다.

“어디를 봐?”에는 **확인한 경로/화면 → 사용자 행동 → 기대 결과**를 준다. 못 본 메뉴 위치·클릭 성공은 만들지 않는다. AI가 가능한 내용·실행 검사는 먼저 하고, 사람이 직접 봐야 할 화면만 이유와 함께 남긴다. 사용자 관측을 AI 관측으로 바꾸지 않는다.

## 분업과 구조 설명이 필요한 경우

여러 세션이면 [병렬 작업](workflows/parallel.md)에서 실제 역할·파일·공통 상태를 확인한다. 일반 질문에 분업 문서를 만들지 않는다.
주요 기능을 이해하거나 지정 문서를 작성할 때는 [지정 양식과 설계 이해](workflows/submission-understanding.md)를 적용한다. 코드의 모든 줄 대신 핵심 입력 한 건이 결과로 이어지는 실제 경로를 설명한다. 설명해 줬다는 사실을 이해 완료로 기록하지 않는다.
