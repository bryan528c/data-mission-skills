# 업무별 빠른 준비 — 사람이 읽는 안내

새 과제의 정답을 미리 고르는 자료가 아니다. 아래 내용은 독립적으로 작성한 일반 업무 준비안이다. 실제 원문·자료·요구 형식이 우선이며, 질문·기능·예시는 고정 요구가 아니다. AI는 이 문서 전체를 매번 읽지 않고 스킬의 유형별 참조를 고른다.

## 같은 시작, 다른 핵심

먼저 “누가 무슨 판단·행동을 해야 하나”를 찾는다. 그다음 실제 입력과 필수 결과, 지정 양식을 확인한다. 어떤 기술로 만들지보다 **첫 결과가 무엇이며 맞는지 어떻게 확인할지**를 먼저 정한다.

| 업무 | 먼저 알아야 할 것 | 작은 첫 결과 | 특히 위험한 오해 |
| --- | --- | --- | --- |
| 비교 분석 | 같은 기간·단위·대상인가 | 비교표 한 묶음과 출처 | 다른 기준의 숫자를 바로 순위화 |
| 변경 검토 | 필수 통과 조건과 선호는 무엇인가 | 후보별 충족·부족·보류 | 근거 없는 점수로 최종 승인 |
| 제약 배정 | 무엇을 어디에 어떤 한도로 놓는가 | 배정안과 별도 제약 검사 | 해를 못 찾음=해가 없음 |
| 일정·선호 | 실제 편성 조건과 관심 지표의 뜻 | 작은 일정과 수정 흐름 | 좋아요=실제 이용수요 |
| 공간 검토 | 좌표·범위·목적과 정보 부족 | 후보별 적합성·근거 | 도면 없이 정밀한 커버 계산 |
| 측정 품질 | 측정 단위·축·적용 기준 | 한 대상의 판정·근거 | 이상 신호=확정 고장원인 |
| 관계·영향 | 관계 종류·방향·시점·출처 | 사실 관계와 가정 시나리오 | 관계도=입증된 인과·예측 |
| 설명·교육 | 대상 수준·학습목표·선행개념 | 한 개념부터 적용까지 | 참고자료 많음=이해 쉬움 |

## 1. 비교 분석

비교의 기준부터 맞추는 일이다. 예를 들어 분기 수치와 연간 수치를 같은 축에 놓았다고 비교가 성립하지는 않는다. 제공 자료에서 어느 기간·단위·범위의 수치인지 먼저 찾는다.

실무자에게는 “이 결과로 어떤 결정을 해야 하며 가장 중요한 비교 기준은 무엇인가?”를 묻는다. 실제 데이터의 불일치를 보여주면 질문이 더 구체적이다.

첫 결과는 원본을 읽고 같은 기준의 작은 비교표를 만드는 것이다. 이후 필요한 조회·필터·설명으로 넓힌다. A는 기준과 계산, B는 확정된 결과 형식을 표시하는 독립 부분을 맡을 수 있다.

설명용 확인: 100에서 120으로 변한 값의 증가율은 20%다. 하지만 기준값이0이면 같은 계산이 정의되지 않는다. 실제 자료에서는 이 경계와 단위·반올림·가중치를 검산한다.

직접 설명할 것: 왜 이 지표·기간을 골랐는지, 어느 처리에서 기준을 맞췄는지, 어디까지 비교 가능한지.

## 2. 변경 검토

더 싼 대안과 바꾸어도 되는 대안은 다르다. 필수 조건 충족, 증거의 상태, 추가 확인을 나눈다. 모든 장점을 합산한 총점이 필수 조건의 실패를 덮어서는 안 된다.

질문은 “검증 자료가 없는 후보를 어떤 상태로 둘지, 무엇이 확인돼야 다음 단계로 갈 수 있는지”다. 답이 없으면 확인 가능한 비교는 계속하되 최종 승인처럼 표시하지 않는다.

첫 결과는 후보 비교와 근거·부족 정보다. A는 필수 조건/비교 기준, B는 실제 요구된 조회·검토 상태 표시를 맡는다. 후보 값을 바꾼 뒤 판정·화면·설명이 함께 바뀌는지 확인한다.

설명용 확인: 필수 시험을 통과해야 한다고 명시돼 있으면 자료 미제공은 합격이 아니다. 저렴하다는 사실만으로 이 상태를 바꾸지 않는다.

직접 설명할 것: 필수와 선호를 나눈 이유, 보류와 실패의 차이, 어떤 근거로 추천했는지.

## 3. 제약 배정

먼저 규칙을 지키는 안을 만들고, 실제로 지키는지 별도로 검사한다. 가장 좋아 보이는 배정과 최적임을 증명한 배정은 다르다.

질문은 대상, 용량, 시간, 고정 조건, 조정 가능한 범위다. 답이 없는 조건은 임시 가정으로 사용자와 정하고 변경 영향을 남긴다. 데이터를 배정 결과에 맞춰 지우지 않는다.

첫 결과는 작은 입력→배정→검사→결과다. A는 규칙·생성·검사, B는 확정된 형식의 결과·수정·조회 부분을 맡는다. 총합뿐 아니라 대상별 누락·중복을 본다. 재계산 뒤 화면과 저장·내보내기도 같은 결과인지 확인한다.

설명용 확인: 한 번에7자리만 있는 공간에9대상을 모두 동시에 배치해야 한다면2자리가 부족하다. 반면 계산이 시간초과됐다는 사실만으로 불가능이 증명되지는 않는다.

직접 설명할 것: 생성과 검사를 왜 나눴는지, 실패와 불가능을 어떻게 구분했는지, 조건 변경 후 무엇이 다시 계산되는지.

## 4. 일정과 선호

일정은 제한된 날짜·슬롯을 편성하는 일이다. 관심도는 추천에 쓰는 정보일 수 있지만 실제 이용수요와 같은 값은 아니다. 안전 관련 정보가 빠졌다면 임의로 채우지 않는다.

질문은 필수 편성 조건, 예외 승인, 관심 자료의 의미다. 첫 결과는 짧은 기간의 일정과 조건 검사이며, 관심 현황은 근거를 구분해서 붙인다. A는 조건과 집계, B는 실제 필요한 달력/표·수정·확인 흐름을 맡는다.

설명용 확인: A 항목20회 반응/100회 노출, B 항목15회 반응/20회 노출은 총 반응수와 반응률의 순서가 다르다. 어느 값을 쓸지는 업무 목적과 표본 한계를 함께 본다.

직접 설명할 것: 관심을 무엇으로 계산했는지, 일정 제약과 어떻게 연결했는지, 편성 불가·예외를 누가 결정하는지.

## 5. 공간 검토

후보 위치가 목적에 적합한지 검토하는 일이다. 범위 계산에 필요한 좌표·단위·가정이 없으면 정밀 결과를 꾸밀 수 없다. 실제 영상 분석이나 장비 제어가 과제 범위인지는 별개다.

질문은 관측·설치 목적과 금지 구역·자료 한계다. 첫 결과는 후보별 장단점·기준 충족·추가 확인으로 만든다. A는 근거와 계산 범위, B는 합의한 후보 비교와 필요한 시각화를 맡는다.

설명용 확인: 두 후보의 커버 구역이 각각 {A,B}, {B,C}라면 겹침을 빼고 합친 구역은3개다. 단순히2+2=4로 보고하지 않는다. 실제 도면의 면적과 단순 집합 예시는 구분한다.

직접 설명할 것: 어떤 정보로 무엇까지 계산했는지, 중복·사각지대·민감 영역을 어떻게 다뤘는지, 실제 검증 한계.

## 6. 측정 품질

측정값의 의미와 판정 기준을 먼저 읽는다. 평균 하나, 여러 축을 합친 값, 시간 변화는 서로 다른 정보를 준다. 통계적 변화 신호와 규격상 합격도 다른 질문이다.

질문은 적용 기준·대상별 차이·요구 조치 수준이다. 첫 결과는 한 대상의 원본값→기준→판정→근거다. A는 단위·매칭·계산, B는 이상 목록과 실제 근거 상세를 맡는다.

설명용 확인: +6과 -6의 산술평균은0이지만 절대값은 모두6이다. 어떤 값이 합격 판정에 필요한지는 실제 규칙을 따라야 한다. 기준이 없으면 정상으로 표시하지 않는다.

직접 설명할 것: 기준을 어디에서 적용했는지, 경계·누락·재측정은 어떻게 다뤘는지, 이상과 원인 추정을 왜 구분했는지.

## 7. 관계와 영향

대상과 그 사이의 관계를 근거 있게 정리하고 변화 시나리오를 보는 일이다. 실제 관계, 해석, 가정을 다른 상태로 둔다. 예쁜 그래프보다 출처와 방향이 먼저다.

질문은 분석 목적, 관계 범위, 시점이다. 첫 결과는 근거를 찾을 수 있는 관계 한 경로와 시나리오다. A는 데이터 모델과 관계 해석, B는 필요한 검색·탐색·표시를 맡는다.

설명용 확인: A→B 공급 관계가 확인됐다고 B→A도 공급한다고 말할 수 없다. 연결 하나가 빠져 있으면 “자료 없음”이지 “관계 없음”이 아니다.

직접 설명할 것: 관계의 방향·종류를 어떻게 저장했는지, 시나리오가 사실과 어떻게 구분되는지, 영향 크기를 단정하지 않은 이유.

## 8. 설명과 교육

학습자가 무엇을 알고 무엇을 새로 할 수 있어야 하는지가 시작점이다. 어려운 용어를 더 많은 어려운 용어로 설명하지 않는다.

질문은 대상의 선행지식과 학습목표다. 첫 결과는 한 개념의 뜻→예→이유→새 사례 적용이다. A는 내용·근거·학습 순서, B는 명시적으로 필요한 화면·콘텐츠 탐색·상호작용을 맡는다. 문서만 요구하면 UI를 만들지 않는다.

설명용 확인: “품질 지표” 정의를 외운 것과, 분모가 달라졌을 때 비교가 달라지는 이유를 설명하는 것은 다르다. 사용자 응답 없이 교육 효과가 검증됐다고 쓰지 않는다.

직접 설명할 것: 순서를 고른 이유, 제공 자료와 보충 설명의 경계, 무엇으로 이해를 확인할지와 실제 확인한 범위.

## 공통 마무리

지정 양식의 각 주장과 실제 코드·자료·검사를 맞춘다. 기술 파일이 있으면 입력·핵심 함수·저장·반환·예외를, 문서형 결과면 자료·변환·구성·확인을 설명한다. 설계만 한 기능, 구현한 기능, 실행 확인한 기능, 사용자가 직접 확인한 기능을 구분한다.

질문: “어떤 입력이 어떤 규칙을 거쳐 결과가 되었나? 왜 선택했나? 무엇으로 확인했나? 아직 무엇을 모르는가?”

이 문서는 AI 허용 단계의 일반 준비 자료다. 제한된 평가의 실제 원문·답안·개인 정보를 공개하거나, AI 금지 단계에서 이 지침으로 지원을 계속하지 않는다.
