# Codex 병렬 작업 빠른 요청문
**사전 준비용 일반 지침. 실제 과제 원문/정답/개인 자료 없음. 과제 README·지정 양식·허용 도구가 항상 우선.**

> 시작 전: 과제 지시서·제공 자료·지정 양식을 먼저 읽는다. 여기의 예상 기능·업무 사례는 실제 필수 요구가 아니다. 같은 세션의 역할명만 지정했다고 파일 소유권·대화 공유가 자동 설정되는 것은 아니다.

## A 시작
너는 총괄 Codex A야. 실제 작업 폴더의 README·데이터·기존 코드·지정 제출 양식을 먼저 확인해. 현재 가져온 data-mission-partner의 START_HERE.md와 SKILL.md를 읽고 **이번 실제 업무에 맞는 참조만** 선택해. [공식 요구/실무자 확인/내 결정/미확인/선택 사항]을 나누고, 첫 작동 결과·검증부터 확보해. 공통 설계·핵심 처리·통합·지정 문서 일치를 담당해. B가 맡을 실제 수정 파일·입출력 계약·완료 기준을 정해 줘. 결과를 바꾸는 업무 결정은 대안·영향과 함께 나에게 확인하고, 이미 승인된 구현은 이어가. 사전 예상 기능을 실제 필수 요구로 취급하지 마.

## B 시작 — A가 담당 범위를 정한 뒤
너는 Codex B야. A와 같은 실제 과제 폴더·파일 상태를 보는지 확인하고 스킬의 필요한 지침 및 A의 최신 공통 기준을 읽어. 담당 결과·수정 가능 파일·입출력·검증 기준이 정해지기 전에는 임의로 개발하지 마. 그 범위만 구현하고 공통 설정·DB·Git·다른 담당 파일은 변경 요청만 남겨. UI가 담당이면 주요 사용자 행동·합의된 정보 구조에 집중하고 불필요한 카드·메뉴·시각효과를 늘리지 마. 첫 화면을 조기 확인하고 실제 입력→처리→결과 연결을 검사해. 완료하면 변경 파일·함수·실행 증거·미확인·통합 주의를 기존 인계 문서에 짧게 기록해.

## A에게 B 작업 할당
실제 지시서와 현재 코드를 기준으로 B가 독립 완료할 한 작업을 골라. 정확한 수정 경로, 읽을 기준 버전, 입력·출력, 완료 조건, 검증 방법을 정해. 같은 파일·DB·설정·포트·Git을 동시에 바꾸지 않게 해.

## 모호한 실무자 답변 반영
실제 확인된 답변과 미확인, 내가 선택할 임시 기준을 구분해. 어떤 기능·데이터·최종 설명이 영향받는지 짧게 알려줘. 실무자가 확정하지 않은 가정을 승인된 사실로 바꾸지 말고 영향 없는 구현은 진행해.

## 최신 기준 전달 (B)
공통 기준의 바뀐 부분을 읽고 네 담당 파일에만 반영해. 변경 결과와 실제 검증을 인계해.

## B 결과 통합 (A)
B의 인계뿐 아니라 실제 변경 파일을 읽어 현 기준과 대조해. B가 쓰기를 마쳤는지 확인하고 입력→출력과 필수 예외를 함께 실행 검증해. 완료 주장만으로 완료 처리하지 마.

## UI 정리
가장 중요한 사용자 행동, 꼭 필요한 정보와 상태, 입력→결과 흐름만 우선해. 불필요한 장식과 중복 정보는 줄이되 요구된 기능은 지우지 마. 임시 데이터와 실제 연동은 구분해.

## 최소 오류·예외 검증
실제 필수 요구와 현재 구현을 비교하고 정상 입력, 경계 입력, 누락·중복·잘못된 입력, 수정/재계산·저장 등 관련된 사례만 실행해 기대값·실제값·근거를 보여 줘. 테스트가 0개인데 통과했다고 하지 마. 화면·저장·내보내기 일치를 확인해.

## 지정 양식·기술 설명 (AI 허용 단계에서만)
실제 지정 양식의 형식·필드·파일명을 보존해. 요구→실무자 확인/내 판단→실제 파일·함수→입력·처리·저장/표시→예외→테스트→한계가 사실대로 연결되는지 검사해. 내가 자기 말로 핵심 흐름을 설명할 수 있도록 이해가 필요한 부분만 짧게 설명해. AI 제안을 내 결정으로 꾸미거나 미구현 기능을 완료로 쓰지 마.

## 제출 전
선택 기능을 멈추고 필수 요구, 실제 작동, 저장 상태, 통합 결과, 지정 양식·코드 일치, 허용된 제출 규격을 최종 확인해. 최종 제출 완료 화면은 내가 직접 확인해.

## 절대 지킬 경계
이 문서는 사전 준비 자료이며 실제 시험 문제·데이터를 외부로 전송하지 않는다. **AI 금지 후속 서술형이 시작되면 모든 관련 Codex 세션의 작업·설명·초안 지원을 중단한다.** 시험 중 외부 앱·브라우저에서 개인 파일을 열어 사용하는 것을 허용된다고 가정하지 않는다.

## 참여 후기에서 참고한 평가 대응 (공식 채점표 아님)
필수 요구를 먼저 완성한다. 실무자의 실제 문제와 모호한 조건을 구체화한다. 중요한 결정은 응시자 본인이 하고 AI 제안을 근거로 수정·통제한다. 코드를 실제 실행하고 예외를 독립 검증한다. 추가 요구는 실무적 가치와 시간에 따라 선택하지, 일부러 기능을 늘리지 않는다. 제출 양식·실제 코드·기록이 맞아야 하고 AI 금지 단계 전에 스스로 설명할 수 있어야 한다. 가점 수치·채점방식은 확인되지 않았다.
